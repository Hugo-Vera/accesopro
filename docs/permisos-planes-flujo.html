2. Tres capas (no mezclar)

A · Plan (Dueño)

Qué módulos y cupos compra el barrio. Solo el dueño de plataforma tilda el plan.

B · Módulo (Barrio)

Catálogo actual (alpr, visitors…). El menú solo muestra lo contratado. El admin no supera el plan.

C · Permiso granular

Qué puede hacer cada usuario. Ej: guardia ve live pero no edita actuadores hasta que le den ops.relay.

5. Planes comerciales

Esencial

core + actuators. Barreras y plano. 1 admin, 2 guardias. Sin ALPR ni portal visitas.

Acceso Pro (recomendado)

+ alpr + visitors + dahua. Demo Las Acacias. Portal propietario, QR, hasta 5 guardias.

Seguridad total

+ panic + fire + attendance. Cronogramas, alta DNI, grants completos.

6. Regla ¿puede?

  1. ¿El plan del tenant incluye el módulo? Si no → menú y API niegan.
  2. ¿El rol base entra al dashboard correcto? (plataforma / ops / portal)
  3. ¿Tiene el capability en user_grants? Si no → UI oculta + API 403.

Nunca confiar solo en ocultar el menú: mismo check en API.
